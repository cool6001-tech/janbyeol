# 잔별 (Janbyeol)

> 별거 아닌 줄 알았던 당신의 오늘이, 이곳에선 누군가의 밤을 비추는 잔별이 됩니다.

화려한 일등성이 아니어도 괜찮습니다. 무심코 흘려보낸 사소한 감정과 일상(잔별)이 모여
거대한 은하수를 이루는, 3D 우주 기반의 감성 소셜 아카이빙 서비스입니다.

Vite + React 프로젝트입니다. 띄운 잔별은 브라우저에 저장되어 다시 열어도 남아 있습니다.

---

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

빌드는 `npm run build`, 빌드 결과 확인은 `npm run preview` 입니다.
Node 18 이상이면 됩니다.

## 잔별 하나는 이렇게 생겼습니다

```js
{
  id, authorId, authorName,
  text, tags: ['비', '바다'],
  photo,        // 올린 사진 (dataURL)
  photoSeed,    // 예시 사진용 씨앗 숫자
  createdAt,    // 시간 축의 기준
  pos: {x,y,z}, // 띄우는 순간 확정, 이후 바뀌지 않음
  warmth,       // 받은 온기 누적
  warmedBy: [], // 누가 온기를 더했는지
  replies: []   // 이어진 별빛
}
```

### 왜 좌표를 저장하나

매번 계산하면 글이 하나 늘 때마다 은하 전체가 재배치되고, *내 별이 어디 있었는지*
감각이 남지 않습니다. 좌표를 기록의 일부로 저장하면 하늘이 곧 기억의 지형이 됩니다.
"저 왼쪽 아래 흐린 별, 작년 장마 때 쓴 거"가 성립하는 이유입니다.

성단이 만들어질 때 닮은 별들이 곁으로 끌려오는 건 **일시적인 화면 연출**이고,
저장된 좌표는 건드리지 않습니다. 전체 은하로 돌아가면 각자의 자리로 돌아갑니다.

## 저장소 계층 — 서버로 옮길 때 고치는 곳

앱의 나머지 코드는 잔별이 어디에 저장되는지 모릅니다. `src/lib/storage.js`의
네 함수만 계약으로 지키면 됩니다.

```js
listStars()           // → Star[]
createStar(star)      // → Star
updateStar(id, patch) // → Star
clearAll()            // → void
```

읽음 기록은 이 계약 **밖**에 따로 있습니다 (`readLog.list / add / clear`).
잔별은 모두의 것이고 읽음은 내 것이라, 같은 상자에 넣지 않았어요.

지금은 `localStorage` 구현이고, 파일 맨 아래에 Supabase 교체 예시와
테이블 정의를 주석으로 남겨뒀습니다. 호출하는 쪽(`useJanbyeol.js`)은 한 줄도
바뀌지 않습니다. 모두 Promise를 돌려주도록 맞춰둔 이유입니다.

로그인을 붙일 때는 `currentUser()`가 로그인된 사용자를 돌려주게만 하면 됩니다.

## 저장이 되니까 가능해진 것들

- **흐려지는 별** — 오래된 잔별일수록 어둡고 작아집니다. 0으로는 가지 않습니다.
  기억은 흐려질 뿐 사라지지 않으니까요. (`time.js`의 `ageFade`)
- **받은 온기 누적** — "별거 아니라 생각한 이 한 줄이, 37명의 밤을 비췄어요."
  서비스의 철학이 숫자로 증명되는 자리입니다.
- **작년 오늘의 별** — 월·일이 맞아떨어지는 예전의 잔별을 다시 밝힙니다.
  우주에서는 따뜻한 고리가 느리게 숨을 쉽니다.
- **감정의 궤적** — 어떤 마음이 많았는지, 어느 달에 몰렸는지.
  차트는 한 가지 색만 씁니다. 길이가 크기를 말하니 색까지 일할 필요가 없습니다.

첫 방문이면 예시 잔별이 한 번 심어집니다(`data/seed.js`).
나의 성단 패널 맨 아래 **하늘 비우기**로 전부 지울 수 있습니다.

## 은하의 모양 (`src/lib/galaxy.js`)

무작위로 뿌리면 절대 나선이 나오지 않습니다. 은하처럼 보이려면 세 가지가 필요합니다.

**수** — 잔별 하나하나가 보여서 은하인 게 아니라, 너무 많아서 뭉개진 빛이 면으로
깔리기 때문에 은하로 보입니다. 그래서 배경 잔별 2만 개를 함께 깔고, 그중 실제로
클릭할 수 있는 건 진짜 누군가 쓴 글뿐입니다. 개수는 `Galaxy.jsx`의 `AMBIENT_COUNT`
한 줄입니다. 밝기를 7단계로 뭉쳐 그려서 색을 바꾸는 횟수를 줄였고, 2만 개의 투영은
객체를 만들지 않고 루프 안에서 직접 계산합니다.

**모양** — 나선 팔은 로그 나선을 따라 배치하고, 중심에 두툼한 핵(bulge), 원반에는
바깥으로 갈수록 얇아지는 두께를 줍니다. 팔 사이도 완전히 비우지 않습니다.

**먼지 띠** — 어둡게 칠하는 게 아니라 **별을 솎아냅니다.** 실제로도 앞쪽 먼지에
가려 별이 안 보이는 것이라서, 팔 안쪽 가장자리의 별을 확률적으로 빼면 그 띠가 생깁니다.

### 한 사람 = 하나의 성단

천문학에서 성단은 은하의 하위 구조입니다. 은하 안 **한 지점에** 중력으로 묶여 뭉쳐
있는 별 무리죠. 흩어져 있으면 성단이 아닙니다. 그래서 이 서비스의 구조도 그대로
따릅니다.

| | 무엇 | 화면 |
| --- | --- | --- |
| 잔별 | 글 하나 | 별 하나 |
| 성단 | 한 사람의 기록 전부 | 은하 안 한 자리에 뭉친 별 무리 |
| 은하 | 모두의 성단 | 수만 개의 성단이 모여 이룬 나선 |

사람마다 은하 안에 자기 자리를 하나 갖습니다(`clusterSiteFor`). 내가 띄우는 잔별은
전부 그 자리 근처에서 태어나요. 그래서 '나의 성단'은 비유가 아니라 사실입니다.

배경 잔별도 매끄럽게 흩뿌리지 않고 성단 단위로 뭉쳐서 만듭니다. **나선 팔의
울퉁불퉁한 결이 곧 아직 다가가지 않은 남의 성단들**이에요. 확대 단계가 자연히
생깁니다 — 멀리서는 성단 하나가 밝은 점, 다가가면 개별 잔별로 풀립니다.

그리고 **공감의 선은 같은 성단 안을 잇지 않습니다.** 이미 뭉쳐 있으니까요.
은하를 가로질러 다른 사람의 성단에 닿는 선만 그립니다. 나는 내 자리에 있지만
내 마음은 저 멀리 누군가에게 닿아 있다는 것 — 그게 화면의 구조 자체가 됩니다.

### 무엇으로 잇는가 (`src/lib/affinity.js`)

선을 어디에 긋느냐가 이 서비스의 전부입니다. 예전에는 **겹치는 태그 개수**가
전부였어요. 그래서 할머니와 엄마가 똑같이 '가족' 하나로 뭉개지고, 기쁨과 슬픔은
완전한 남남이었습니다. 사람이 느끼는 닮음은 그렇지 않습니다.

축을 둘로 나눴습니다 — **소재**(무엇에 대한 이야기인가)와 **감정**(어떤 마음인가).

```
점수 = 10 × (0.7 × 소재 닮음 + 0.3 × 감정 닮음)
```

| | 점수 |
| --- | --- |
| 할머니에 대한 즐거운 기억 ↔ 할머니에 대한 즐거운 기억 | **10.0** |
| 할머니에 대한 즐거운 기억 ↔ 할머니에 대한 슬픈 기억 | **7.5** |
| 할머니에 대한 슬픈 기억 ↔ 할머니 댁의 쓸쓸함 | **9.4** |
| 할머니에 대한 즐거운 기억 ↔ 엄마에 대한 슬픈 기억 | **4.4** |
| 할머니에 대한 즐거운 기억 ↔ 바다에서의 슬픔 | **0.6** |

**소재가 같으면 감정이 반대여도 여전히 가깝습니다.** 같은 것을 겪은 사람이니까요.
0.7 / 0.3 이라는 배분은 "소재가 같고 감정이 정반대일 때 7점"이 되도록 맞춘
값입니다. 소재에는 층이 있어서(`group`) 할머니와 엄마는 같은 사람은 아니지만
남남도 아닙니다 — 같은 key면 1.0, 같은 group이면 0.55.

감정은 같으냐 다르냐로 보지 않고 **좌표**로 둡니다. 슬픔과 고독은 슬픔과 기쁨보다
가까운데, 일치/불일치로만 보면 그 차이가 사라지거든요. 좋고 싫음(valence)과
깨어 있음·가라앉음(energy) 두 값으로 거리를 잽니다.

**점수는 화면에 나오지 않습니다.** 얼마나 가까이 둘지를 정할 뿐이에요.
3점을 못 넘으면 아예 잇지 않고, 넘은 짝은 점수가 높은 순으로 이어 붙이되
한 잔별이 가질 수 있는 선의 수를 제한합니다. 그래서 **가장 닮은 사람이 바로 옆에
오고, 덜 닮은 사람은 자연히 한 단계 건너에 놓입니다.**

잔별을 눌러 이웃이 곁으로 모일 때도 같은 점수가 거리가 됩니다 — 10점은 코앞
(`ORBIT_NEAR`), 3점은 그 바깥(`ORBIT_FAR`). 그리고 **아무와도 이어지지 않은
잔별은 남기지 않습니다.** 문턱을 못 넘었더라도 가장 닮은 한 사람과는 잇습니다.
그물에서 끊긴 별은 누구에게도 발견될 수 없으니까요.

### 선은 두 겹입니다 (`src/lib/graph.js`)

**앞 — 이야기의 줄기.** 같은 사람의 잔별을 띄운 순서대로 이은 실입니다. 태그가 아니라
시간으로 잇습니다. 이건 공감이 아니라 한 사람이 지나온 길이니까요. 성단을 가로지르는
한 줄기가 되고, 내 것은 따뜻하게 또렷합니다. 남의 줄기는 희미하게.

**뒤 — 공감의 그물.** 은하를 가로질러 다른 사람의 잔별에 닿는 선. 같은 성단 안은
잇지 않습니다. 늘 희미하게 깔려 있다가, 잔별을 누르면 주인공이 됩니다.

### 별빛이 번져나간다

잔별을 누르면 거기서 **1겹 → 2겹 → 3겹 → 4겹**으로 차례차례 뻗어나갑니다.
내 글에 닿은 낯선 사람의 글, 다시 그 글에 닿은 또 다른 사람의 글.
선 끝에 작은 점이 달려 빛이 실제로 건너가는 게 보이고, 겹이 깊어질수록
따뜻한 빛에서 먼 별빛 쪽으로 색이 식습니다.

카드에는 이렇게 적힙니다 — *"이 마음은 7명의 잔별 24개에 닿아 있어요."*
비슷한 처지의, 생각이 같은 사람이 이만큼 있다는 걸 숫자와 그림으로 동시에 말하는
자리입니다. 깊이는 `App.jsx`의 `TRACE_DEPTH`, 그물의 촘촘함은 `buildGraph(stars, 4)`의
두 번째 인자입니다.

### 누른 별로 **다가갑니다**

연결된 잔별은 거의 언제나 은하 건너편에 있습니다. 실제로 재 보면 1겹 이웃까지가
1,700~2,300 단위인데 은하 반지름이 1,650이에요. 그래서 *내 별을 크게 보기*와
*연결된 별을 함께 보기*는 좌표를 그대로 둔 채로는 동시에 성립하지 않습니다.
둘 다 담으려면 결국 은하 전체가 보이는 거리까지 물러나야 하니까요.

택한 답은 **닿아 있는 잔별을 잠시 곁으로 끌어오는 것**입니다.

- 누른 잔별이 화면의 한가운데가 되고 카메라가 그 앞까지 내려앉습니다
- 1겹은 **닮은 만큼 가까이** 섭니다 — 10점이면 `ORBIT_NEAR`, 3점이면 `ORBIT_FAR`.
  2겹은 그 바깥 `ORBIT_R2` (`App.jsx`)
- 3겹·4겹은 제자리에 남아, 이 마음이 아직 더 멀리까지 뻗어 있다는 걸 선으로 말합니다
- 카드는 그 별 **옆에** 떠서 얇은 꼬리선으로 이어집니다

저장된 좌표(`star.pos`)는 건드리지 않습니다. 화면 위에서만 잠시 모이는 연출이고,
'전체 은하'를 누르면 각자의 자리로 흩어집니다. 이미 '공감 성단'에서 쓰던 규칙과
같은 것이에요.

**카드를 닫아도 줌인은 남습니다.** `selectedId`(무엇을 보고 있는가)와
`cardOpen`(글을 읽고 있는가)을 따로 두었기 때문입니다. 그래서 카드를 닫고
곁으로 모여든 남의 잔별을 누르면, 이번엔 그 별이 중심이 되어 같은 일이 되풀이됩니다.
은하를 한 별에서 다음 별로 건너다니게 되는 거죠.

#### 크기의 상한

별은 아무리 다가가도 커지지 않았습니다. 반지름이 `Math.min(rad, 4.4)`로
눌려 있었거든요. 배경의 수많은 별이 덩어리로 뭉치지 않게 하려는 값인데,
지금 보고 있는 별에까지 적용될 이유는 없습니다. 그래서 상한을 역할별로 나눴습니다 —
고른 별 11, 곁으로 끌려온 별 7, 나머지는 그대로 4.4 (`Galaxy.jsx`).

### 선은 사실 세 겹입니다 — 별길

3D 하늘에서는 **내가 읽은 별인지 아닌지를 알 방법이 없었습니다.** 목록형 피드라면
순서와 방문 표시가 기억을 대신해 주지만 여기엔 둘 다 없고, 카메라가 계속 돌고
별을 누르면 이웃이 궤도로 모였다 흩어지니 위치조차 단서가 못 됩니다. 게다가
별의 생김새는 온기와 나이만 말하고 정체성은 말하지 않아서, 두 번째 보는 별과
처음 보는 별이 물리적으로 구별되지 않았어요.

읽음을 **상태**가 아니라 **경로**로 표현했습니다. 읽은 순서대로 잇는 세 번째 선입니다.

| | 무엇 | 누구의 것 |
| --- | --- | --- |
| 공감의 그물 | 닮은 마음끼리 | 모두의 것 |
| 이야기의 줄기 | 한 사람이 지나온 길 | 각자의 것 |
| **별길** | **내가 읽어나간 길** | **오직 나의 것** |

#### 색 — 왜 초록인가

이 하늘에서 파랑은 별빛(`COOL`)이고 호박색은 온기(`WARM`)입니다. 둘 다 이미 뜻을
가진 색이라, 별길이 그중 하나를 쓰면 *"이게 온기인가 별빛인가"* 하게 됩니다.
처음엔 호박색으로 그렸다가 실제로 그 문제가 났어요.

남은 자리가 초록이었습니다. 밤하늘의 오로라 같은 색이라 어색하지 않고, 무엇보다
**한눈에 다른 것**입니다. 바꾸고 싶으면 `Galaxy.jsx`의 `ROAD_RGB` 한 줄입니다.

#### 시간이 지우는 길

- **하루 반까지 그대로, 사흘이면 사라집니다** (`ROAD_FULL_MS` / `ROAD_GONE_MS`).
  처음엔 "몇 번째로 읽었는가"로 흐리게 했더니 스무 개쯤 읽으면 앞의 것들이
  보이지 않아서 결국 또 헷갈렸습니다. 기준을 순서에서 **시간**으로 바꿨어요.
  사흘이면 다시 읽어도 괜찮은 글이 됩니다.
- **세 시간 넘게 사이를 두고 읽었으면 잇지 않습니다** (`ROAD_GAP_MS`).
  어제 읽은 별에서 오늘 읽은 별로 긴 선이 날아가면 길이 아니라 실수처럼 보여요.
  한 번의 산책마다 길이 따로 납니다.
- **매듭.** 길이 지나간 잔별마다 작은 초록 고리가 둘립니다. 선만으로는 별 무리
  안에서 어느 것이 읽은 별인지 애매하고, 오늘의 산책이 한 개뿐이라 선이 없을 때도
  이것만은 남습니다.
- **다시 읽어도 길은 다시 나지 않습니다.** 매번 끝으로 옮기면 길이 되감기며
  고리가 생겨요. 한 번 난 자리에 그대로 두는 편이 지도로서 안정적입니다.
- **내 잔별도 길에 놓입니다.** '나의 성단'에서 길이 내 별에서 출발해야, 내가 어느
  이야기에서 시작해 어디까지 걸어갔는지가 보이니까요. 그 시점에서는 남의 잔별이
  저물지만 별길만은 읽히도록 밝기에 바닥을 둡니다.
- 카드를 스쳐 연 것만으로는 읽은 게 아닙니다. **1.2초 머물러야** 한 칸 자랍니다.

#### 읽음은 내 것입니다 (`storage.js`의 `readLog`)

이 기록만은 `star` 안에 넣지 않았습니다. 온기는 모두의 것이지만 읽음은 내 것이에요.
읽음이 글쓴이에게 보이는 순간 카톡의 '1' 같은 압박이 생깁니다. 읽씹당했다는 감각은
이 서비스가 절대 만들면 안 되는 감정이라, 이 기록은 내 브라우저 밖으로 나가지
않습니다. 서버로 옮기더라도 남에게는 보이지 않는 개인 테이블이어야 합니다.

순서가 곧 데이터라 배열입니다. 하늘의 별길을 놓쳤더라도 카드를 여는 순간
*"3일 전에 읽었어요"* 한 줄이 알려주고, '나의 성단' 아래에서 별길만 따로 지울 수
있습니다(띄운 잔별은 그대로).

### 성단 안에서의 자리

```js
export const CLUSTER_MAPPING = {
  inward: true,    // 오래된 잔별일수록 성단 중심으로 잠긴다
  byEmotion: true, // 같은 마음은 성단의 같은 쪽에 모인다
}
```

실제 성단도 오래된 별이 안쪽에 모이고 새 별은 바깥에서 태어납니다.

좌표는 id에서 나온 결정적 난수로 정해지므로 같은 잔별은 언제나 같은 자리입니다.
그래도 좌표를 저장해 두는 이유는, 나중에 배치 규칙을 바꿔도 옛 기록의 자리가
지켜지도록 하기 위해서입니다. 규칙을 바꿀 때는 `useJanbyeol.js`의 `POS_VERSION`을
올리면 저장된 잔별이 새 은하 위로 옮겨집니다(글과 온기는 그대로).

## 하늘을 보는 두 시점

오른쪽 위 버튼 두 개는 **다른 화면이 아니라 같은 우주를 보는 두 시점**입니다.

| | 전체 은하 | 나의 성단 |
| --- | --- | --- |
| 보이는 것 | 모두의 잔별 | 내 잔별만 밝고, 나머지는 배경으로 저묾 |
| 카메라 | 은하 전체가 담기는 거리 | 내 잔별들의 무게중심으로 내려앉음 |
| 곁들여 열리는 것 | — | 회고 패널 (온기 누적 · 감정의 궤적 · 작년 오늘) |

구현은 `mineMode` 상태 하나입니다. `Galaxy`가 이 값을 받아 내 잔별이 아닌 별의
`dim`을 0.12로 서서히 끌어내리고(끄는 게 아니라 저물게 합니다), 연결선 투명도에도
같은 값을 곱합니다. 카메라는 `App.jsx`의 `enterMine()`이 내 잔별들의 평균 좌표와
퍼진 정도를 계산해 거리를 정합니다.

'전체 은하'를 누르면 `dim`이 다시 1로 돌아오면서 모두의 잔별이 떠오릅니다.

### 성단이라는 말의 두 쓰임

- **나의 성단** — 내가 띄운 잔별 전부. 영구적입니다.
- **공감 성단** — 방금 띄운 글에 닮은 마음들이 잠시 모여든 것. 전체 은하로 돌아가면 흩어집니다.

같은 '성단'이지만 지속성이 다르므로 화면에서도 다른 이름으로 부릅니다.

## 좁은 화면 — 하늘이 먼저

휴대폰에서는 카드와 회고 패널이 화면 아래 절반을 덮고 입력창이 150px를 더
가져가서, 정작 봐야 할 하늘이 위쪽 4분의 1만 남아 있었습니다. 게다가 확대·축소는
`wheel` 이벤트로만 구현돼 있어서 **손가락으로는 아예 다가갈 수가 없었어요.**

바뀐 것은 네 가지입니다.

| | 전 | 후 |
| --- | --- | --- |
| 회고 패널 | 하단 52%를 항상 차지 | 손잡이만 남기고 접히는 바텀시트 (톡 누르거나 쓸어서 여닫기) |
| 잔별 카드 | 입력창 위에 끼어든 상자 | 아래에서 올라오는 시트 |
| 입력창 | 늘 150px | 평소엔 한 줄, 쓰기 시작하면 펼쳐짐 |
| 확대·축소 | 없음 | 두 손가락으로 벌리고 오므리기 |
| 첫 화면 거리 | `3400` 고정 | 화면 크기에서 계산 (`cosmosDistance`) |

마지막 줄이 "새로 고치면 과도하게 확대돼 보이는" 증상의 원인이었습니다. 3400은
1440px 화면에 맞춰 고른 값이라, 휴대폰에서는 반지름 1,650의 은하가 화면 반폭
183px 안에 들어올 수가 없었어요. 화면이 좁을수록 더 멀리 물러나야 같은 그림이
담깁니다. 창 크기가 바뀌면(회전 포함) 전체 은하 시점은 다시 맞춥니다.

멀리서 보면 배경 잔별이 한 픽셀에 여러 개 겹치므로 밝기도 그만큼 보정합니다
(`Galaxy.jsx`의 `ambientGain`). 안 하면 좁은 화면에서만 은하가 흐려집니다.

그리고 **가려진 만큼 하늘의 중심을 옮깁니다.** 위아래 UI가 차지한 높이를 재서
남은 띠의 한가운데로 카메라의 화면 원점을 밀어 올려요(`Galaxy.jsx`의 `cam.oy`,
`geometry.js`의 `project`). 시트가 올라와도 보고 있던 별이 그 뒤로 숨지 않습니다.

별을 고르는 반경도 손가락에 맞춰 넓혔습니다 (마우스 28px, 터치 42px).

## 세계관 용어

| 화면에서 | 실제로는 |
| --- | --- |
| 잔별 띄우기 | 새 글 작성 + 사진 1장 |
| 나의 성단 | 마이페이지 / 내 피드 (+ 시점 전환) |
| 공감 성단 | 방금 띄운 글과 유사도가 높은 잔별들의 임시 모임 |
| 온기 더하기 | 좋아요 — 누르면 별빛이 따뜻한 색으로 물듭니다 |
| 별빛 이어가기 | 댓글 |

우주 뷰에서 사진은 **절대 보이지 않습니다.** 사진을 품은 잔별은 오라 고리와
회절 스파이크로만 다르게 반짝이고, 카드를 열어야 어두운 톤으로 깔린 이미지가 나타납니다.
